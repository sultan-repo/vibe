# Optional verification reuse

Use this pattern only when a project repeats the same expensive verification before a push or release. It is not registered in Vibe's plugin hooks and adds no default gate. The coordinator adapts existing project scripts and hooks during authorized work; the user does not run setup or mode-selection commands.

## Contract

- `verification-cache.py run|check|pre-push --mode quick|full --context-command SCRIPT [--full-includes-quick] [--fresh] -- GATE [ARGS...]` calls the project gate with `quick` or `full` appended. The adapter selects the project's existing checks. `run` and `pre-push` reuse identical passing evidence; `--fresh` deliberately runs again. Use the same adapter and options in the coordinator, push hook and release script.
- The project context executable prints a stable, nonsecret signature of inputs outside the committed tree: relevant runtime/dependency setup, ignored configuration and owned fixtures. The helper compares its output before and after every run or reuse, rejecting changes. `--context SIGNATURE` is an alternative only for explicitly immutable inputs. Tracked lockfiles and verification scripts already belong to the tree. Hash relevant inputs without logging secrets. Do not cache history-sensitive, live-service or changing external-state checks; run those separately. Give verification exclusive ownership of the checkout and its declared inputs for the duration of the run.
- Full satisfies quick only with the explicit `--full-includes-quick` contract on both producer and consumer. Keep each mode's successful evidence. A fresh failed or interrupted run invalidates prior evidence for that tree/context. Time is provenance, not a promise that external inputs remained unchanged.
- A pass requires a clean checkout before and after, including untracked files and submodule changes, with unchanged HEAD and tree. Ignored inputs are the signature's responsibility. Dirty verification cannot certify committed code being pushed. A different pushed tree needs its own cached evidence or a clean checkout of that ref; never bypass the hook to avoid a repeat.

The helper keeps small atomic JSON markers and an exclusive-run lock in `git rev-parse --git-path vibe-verification`, including linked worktrees. It keys evidence by tree, context, adapter command, helper implementation and mode-coverage contract. Raw context and commands are not stored in markers. Malformed records miss the cache. An interrupted process can leave a lock: the coordinator confirms that it stopped before removing that Git-private lock. Worktrees have separate evidence; changing checkouts in one worktree preserves evidence for earlier trees.

## Change-aware coverage

The helper's modes remain **quick/full**. A project's adapter may implement affected or expanded checks under quick; release uses full with the complete required suite. These policy scopes are not new CLI modes. The helper does not infer dependencies, prove coverage or detect a runner that reports success after selecting zero tests: the adapter must reject an empty selection for changed behavior and preserve required acceptance checks.

For selective checks, the declared context must include the selection contract: cumulative comparison base, test-map/adapter version, filters and browser/device projects for each mode, plus relevant external inputs. Do not reuse a marker across different selection scopes just because the code tree matches. Full satisfies quick only when it demonstrably covers every required quick check; never relabel a subset as full. If scope cannot be represented safely, do not cache that selection. Reuse removes duplicate execution, not coverage, required CI or exact-HEAD review.

## Project hook adoption

`pre-push.template` is an example for a project deploying only its `release` branch. Before adopting it, the coordinator verifies the actual deployment boundary, adjusts the full-check refs, supplies `scripts/verification-context`, adapts `scripts/verify.sh` to the mode argument and copies the helper to `.githooks/verification-cache.py`. Use existing equivalent paths where available. Preserve the project's `core.hooksPath` arrangement and unrelated guards; do not overwrite an existing hook or retain its duplicate full-gate invocation. The template demonstrates forwarding both arguments and stdin to existing guards.

Intermediate non-deploying branches and routine feature deployments, including auto-deploying merges, use the project's affected/expanded quick checks plus feature-scoped acceptance and relevant deployment smoke/rollback evidence. Gate a stable integrated formal production release/promotion candidate in full before publishing or promoting it, and reuse valid matching evidence for the push/release. An explicit owner E2E request, unbounded impact or existing project integration gate may require full checks earlier. Explicit project integration gates still apply; a feature milestone alone is not a full-suite trigger. Changes to the candidate or declared context require new relevant evidence. Complete tracked decision/status edits before the final gate and keep its result in Git-private storage, CI or PR records, so reporting does not change the verified tree. Never record an unobserved result as passed.

During authorized adoption, validate a new selective mapping with the bounded comparison in Build's `references/testing-policy.md` before relaxing an existing gate. Preserve old project gates until their replacement is validated; upgrading Vibe alone does not migrate project hooks or authorize disabling CI.

Pre-push examines every actual local object ID from Git's stdin, including non-HEAD branches and annotated tags to commits. The template groups refs by required mode, so a release and its lower branches can share one push without imposing full checks on every branch. Multiple refs must all have adequate evidence; deletion-only pushes need no source or context checks. Non-commit tags/objects require project-specific handling and are rejected. Existing authorization, required CI and independent-review approval are unaffected: cached executable tests are not a review or deployment permission.

## Evidence-only enforcement (opt-in)

`check --mode quick|full ... -- GATE [ARGS...]` validates existing evidence for the current candidate. `pre-push --require-evidence` validates every actual pushed tree under the caller's required mode. Both use the same context, adapter identity, clean/stable snapshot, lock and coverage contract as `run`; neither launches the gate on a miss. The inexpensive context-signature provider and local Git inspection still run. Missing, stale, malformed, insufficient or pending evidence rejects the operation. `--fresh` is incompatible with evidence-only enforcement.

The coordinator runs required verification separately with `run`, then uses `check` or the evidence-only push hook with identical arguments. In the template, opt in by changing the literal `require_evidence=()` to `require_evidence=(--require-evidence)` during authorized adoption. Do not use a push-time environment override to select protection. Configure every actual production-triggering ref, preserve unrelated guards and required CI, and reject a promotion until its full evidence exists. Keep default run-on-miss behavior when no separate orchestration path is ready.

The adapter receives bare `quick` or `full`, not `--quick`. Test that contract rather than silently falling back to full or skipping browser acceptance. Full/quick coverage and context must still be represented; this action is not a test selector, scheduler, review approval or deployment permission. A helper update changes its identity, so old markers intentionally require fresh evidence.

When useful, verify and promote from the same stable candidate worktree while independent coding continues elsewhere. Reserve or isolate shared ports, databases and browser capacity. Collect results and persist pending-run metadata; missing/cancelled evidence never succeeds. Finalize tracked policy/status edits before the full gate. Do not add a shared evidence store or broadly ignore Markdown to avoid conservative cache misses.
